JobGenie Conjures a Smarter Way to Apply

Resume intelligence, ATS simulation and grounded AI analysis, so every application is better informed.

By S. Agrawal, Our Engineering Correspondent

Job searching involves more than finding openings. Candidates also need to understand how their experience matches each role. JobGenie brings resume parsing, ATS-score simulation and job-description matching into one application copilot, helping candidates make better decisions before they apply.

At its core, JobGenie uses a RAG pipeline to ground LLM outputs and reduce hallucination in match scoring. An LLM analytics dashboard shows how each application fits, while multi-resume A/B testing makes it easy to compare versions of a resume.

The platform also tracks interviews to keep the whole process organised. The backend runs on Python and FastAPI, with PostgreSQL for data and Docker for shipping. It is live at jobgenie.tech.

At a glance

  • Resume parsing, ATS-score simulation and job-description matching.
  • RAG-grounded match scoring and an LLM analytics dashboard.
  • Multi-resume A/B testing and interview tracking.

Built with

Python · FastAPI · Gemini API · RAG · Docker · PostgreSQL

PhoniX Unmasks the Voice Behind the Deception

A Flutter app combines live call audio analysis with deep-learning detection to flag AI-generated voices.

By S. Agrawal, Our Engineering Correspondent

Voice phishing is harder to recognise as AI-generated voices become more convincing. PhoniX tackles this by analysing incoming call audio in real time. Its pre-trained TensorFlow model examines voice characteristics and alerts the user when a voice is flagged as deepfake or AI-generated.

When a call comes in, the app intercepts its audio stream and feeds it into the detection model. The model analyses the voice and raises real-time alerts, giving users an extra layer of awareness during a potentially fraudulent call.

PhoniX is built as a Flutter mobile app, with Firebase for secure sign-in and data storage. The model reached 89.68% accuracy, and the project took fifth place at CSA Hackathon 3.0 at UPES.

At a glance

  • Real-time interception and analysis of incoming call audio.
  • TensorFlow voice detection with 89.68% accuracy.
  • Flutter app with Firebase sign-in and storage.

Built with

Flutter · TensorFlow · Firebase · Audio

Three Architectures, One Recommendation Challenge

An experimental comparison of recurrent networks and Kolmogorov-Arnold Networks on real e-commerce clickstream data.

By S. Agrawal, Our Engineering Correspondent

What makes a good next-item recommendation? This research project explores three neural architectures for session-based recommendation on the YooChoose e-commerce clickstream dataset: a GRU-based recurrent model, a custom KAN and a hybrid of the two.

The KAN was implemented from scratch with B-spline layers and attention pooling. The hybrid lets a KAN layer refine the GRU output. All three models share one training pipeline, so the comparison stays fair.

The experiments use 50K sessions and more than 128K samples, benchmarked on HR@10, NDCG@10 and accuracy. The best results reached 58.08% HR@10 and 39.42% NDCG@10.

At a glance

  • GRU, from-scratch KAN and hybrid GRU+KAN compared.
  • B-spline KAN layers and attention pooling, written by hand.
  • 58.08% HR@10 and 39.42% NDCG@10.

Built with

Python · PyTorch · GRU + KAN · Deep Learning

Launch Cadence: Mission Control, Simplified

A role-based rocket launch management system built with nothing but Python’s standard library and flat files.

By S. Agrawal, Our Engineering Correspondent

Launch Cadence brings rocket launch management and customer bookings into a single console application. It separates admin work from customer workflows: admins manage rocket specifications and launch schedules, while users browse rockets and reserve launch slots.

Admins set rocket dimensions, mass, payload capacity to LEO, GTO and SSO, and pricing. They also schedule launch slots with leap-year-aware date validation. Users can sign up, log in, browse what is available and book a launch.

The app keeps active bookings, booking history and per-user remarks. Everything is stored in plain text files and it uses only the Python standard library, so it runs anywhere with no dependencies.

At a glance

  • Separate admin and customer roles.
  • Rocket specs, pricing and leap-year-aware scheduling.
  • Flat-file storage for bookings, history and remarks.

Built with

Python · Standard library · Flat-file storage · CLI

The Library Ledger: Every Book Accounted For

A desktop library management system that connects book and member records to a relational database.

By S. Agrawal, Our Engineering Correspondent

Running a library means keeping track of both the collection and its members. This team project is a Java Swing desktop application for managing books and member records, with database-backed workflows for issuing and returning books.

The app brings core library operations into one desktop interface. Librarians work with book and member records through Swing screens, while issue and return workflows handle circulation.

A relational SQL database stores every record. The project pairs Java desktop development with database operations for a structured approach to running a library.
